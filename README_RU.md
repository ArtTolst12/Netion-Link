# Netion Link

[English](README.md) · **Русский**

Доступ к сетевому соединению основного устройства через локальный HTTP- или SOCKS5-прокси — без root-прав.

**Версия 3.1.8** · Android 7.0+ · [Скачать](https://github.com/ArtTolst12/Netion-Link/releases)

## Как это работает

При обычной раздаче интернета Android, как правило, не направляет подключённые устройства через VPN основного телефона. Netion Link использует для этого прокси на уровне приложения:

- **Сервер:** запускает HTTP/HTTPS CONNECT и SOCKS5 на основном телефоне. Исходящие соединения следуют его маршрутизации, в том числе внешнему VPN, если тот обслуживает трафик Netion Link.
- **Клиент:** через VPN-интерфейс Android перенаправляет поддерживаемый IPv4 TCP-трафик и DNS-запросы на прокси основного телефона. Другие устройства могут подключаться напрямую через приложения или настройки с поддержкой прокси.

Netion Link не предоставляет VPN-серверы, прокси-подписки или собственный облачный сервис. Интернет и при необходимости внешний VPN на основном устройстве пользователь настраивает самостоятельно.

## Возможности

- Локальное подключение через точку доступа Wi-Fi, общую Wi-Fi-сеть или USB-модем, если устройства доступны друг другу.
- HTTP-прокси, HTTPS-туннели через CONNECT и TCP-соединения SOCKS5.
- Встроенный VPN-клиент Android с явным выбором протокола HTTP/SOCKS5.
- QR-подключение с передачей адреса сервера, портов и протокола.
- Автоматический выбор другого порта, если запрошенный занят.
- Счётчики трафика, состояние соединения и английский журнал диагностики с копированием отчёта.
- Foreground-службы и системные блокировки энергосбережения для фоновой работы — с учётом ограничений Android и прошивки.
- Интерфейс на русском, английском, немецком, французском, испанском, португальском, польском, китайском, японском и корейском языках.

## Начало работы

Установите доступный APK из [Releases](https://github.com/ArtTolst12/Netion-Link/releases) либо [соберите приложение из исходников](#сборка-из-исходников). Наличие тега исходников не означает, что APK этой версии уже опубликован.

### Android → Android

**На основном телефоне — сервере:**

1. Подключитесь к интернету. Если хотите раздавать соединение внешнего VPN, сначала включите его и убедитесь, что Netion Link не исключён из маршрутизации.
2. Включите точку доступа Wi-Fi с паролем либо подключите оба устройства к доверенной локальной сети. USB-модем также подходит, если принимающее устройство поддерживает такое подключение.
3. Откройте вкладку **«Сервер»** и запустите раздачу.
4. Проверьте отображаемый адрес сервера и действующие порты. Откройте QR-код подключения.

**На принимающем телефоне — клиенте:**

1. Подключитесь к точке доступа основного телефона или к той же локальной сети.
2. Откройте вкладку **«Клиент»** и отсканируйте QR-код либо вручную укажите адрес, порт и протокол сервера.
3. Запустите VPN-подключение и подтвердите системный запрос Android.

Android обычно допускает только один активный VPN для пользователя/профиля. Встроенный клиент может заменить другой VPN на принимающем телефоне; внешний VPN раздающего устройства работает на отдельном основном телефоне.

### Компьютер или другое устройство с поддержкой прокси

1. Подключитесь к точке доступа или локальной сети основного телефона.
2. Настройте **HTTP-прокси** или **SOCKS5-прокси** в приложении либо операционной системе — в зависимости от поддержки клиента.
3. Используйте адрес и действующий порт со вкладки сервера. Стандартные порты — **8080** для HTTP и **1080** для SOCKS5, но при занятости они могут измениться.

Например, в Windows раздел **«Параметры → Сеть и Интернет → Прокси-сервер → Настройка прокси вручную»** задаёт HTTP-прокси. Для SOCKS5 нужен клиент с его поддержкой. Системная настройка прокси не означает перенаправление трафика всех приложений.

## Поддерживаемый трафик и ограничения

| Возможность | Текущее поведение |
|---|---|
| IPv4 TCP | Перенаправляется встроенным VPN-клиентом через HTTP CONNECT или SOCKS5 |
| DNS | Обрабатывается VPN-клиентом; при настроенном прокси нет скрытого перехода на прямой DNS |
| Произвольный UDP / QUIC | Не перенаправляется; выбор SOCKS5 не включает UDP ASSOCIATE |
| IPv6 | Не поддерживается встроенным VPN-клиентом |
| IPv4-фрагменты | Отбрасываются; сборка фрагментов не реализована |
| Обязательная работа внешнего VPN | Зависит от маршрутизации основного устройства; собственного kill switch для внешнего VPN нет |

Игры, голосовые и видеозвонки, а также приложения с неподдерживаемым трафиком могут не работать. Совместимость и устойчивость фоновой работы зависят от устройства, версии Android, сети и настроек внешнего VPN.

## Безопасность и приватность

- Используйте только **доверенную локальную сеть или точку доступа с контролем подключения**. У прокси нет собственной аутентификации клиентов и TLS-защиты. Не открывайте его порты в интернет.
- HTTPS остаётся зашифрованным между клиентским приложением и целевым ресурсом, но сам прокси не добавляет шифрование к изначально незашифрованному трафику приложений.
- В приложении нет рекламы, сторонних трекеров и автоматической отправки диагностики. Соединения устанавливаются с настроенным прокси и целевыми сервисами, а не с собственным сервером Netion.
- Журнал ограничен по размеру и хранится в памяти. Скопированный отчёт может содержать адреса прокси/назначений и сведения об устройстве — проверяйте его перед передачей третьим лицам.
- Если внешний VPN отключится или исключит Netion Link, основное устройство может использовать прямой маршрут. Проверьте маршрутизацию и блокировки внешнего VPN; не полагайтесь на наличие kill switch в Netion Link.

## Если соединение не работает

Сначала проверьте **текущие** адрес, порт и протокол сервера. Автоматическая смена порта, изоляция клиентов локальной сети, переключение сетей и фоновые ограничения могут мешать подключению даже при запущенных приложениях.

`Connection reset by peer` означает сброс TCP-соединения при обмене с прокси. По одному клиентскому журналу нельзя определить, произошёл ли сбой на сервере, в сети или во внешнем VPN. Сохраните отчёты **обоих устройств** за одно время. В версии 3.1.8 уточнены этапы подключения, причины сбросов и таймаутов, но это не гарантирует отсутствие внешних сетевых отказов.

Не отключайте защиту сокетов, проверку TLS и не добавляйте прямой обход прокси ради сокрытия ошибки.

## Сборка из исходников

### Требования

- **JDK 25**, выбранный в `gradle/gradle-daemon-jvm.properties`.
- **Android SDK Platform 37** и **Build Tools 36.0.0**, принятые лицензии SDK.
- Android Studio с поддержкой **Android Gradle Plugin 9.4.1** либо Android SDK command-line tools.
- Включённый в проект **Gradle wrapper 9.6.0**. Отдельная установка Gradle не нужна.

Совместимость Java-исходников и байткода установлена в 11; это не версия JDK для запуска Gradle. Минимальный API устройства — 24, целевой — 37.

```bash
git clone https://github.com/ArtTolst12/Netion-Link.git
cd Netion-Link
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

В Windows PowerShell замените `./gradlew` на `.\gradlew.bat`, в Command Prompt используйте `gradlew.bat`. Если архив не сохранил право выполнения в Linux/macOS, сначала выполните `chmod +x gradlew`.

Укажите путь Android SDK в Android Studio либо в своём неотслеживаемом `local.properties` (`sdk.dir=...`). Для первой сборки нужен интернет, чтобы загрузить ещё не закешированные Gradle, JDK и зависимости.

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.

Для распространяемой сборки настройте свой ключ релизной подписи через **Build → Generate Signed Bundle / APK…**. Одна команда `assembleRelease` не настраивает подпись релиза. Не добавляйте закрытые ключи и пароли в Git; сохраните существующий ключ, если требуется обновление поверх уже установленной сборки.

### Проверка

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Unit-тесты используют локальные фикстуры, включая TCP-серверы на loopback. Они не заменяют проверку VPN-разрешений Android, foreground-служб, переключения сетей, камеры, буфера обмена и интерфейса на реальных устройствах.
